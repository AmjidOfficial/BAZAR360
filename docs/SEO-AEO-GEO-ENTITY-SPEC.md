# Bazar360 SEO / AEO / GEO / Entity Specification

## Goal
Make Bazar360 discoverable through search engines, answer engines and local/entity discovery while keeping every indexed fact authoritative and current.

## Canonical entities
- Vehicle listing
- Brand
- Model
- City/location
- Showroom/dealer
- Seller profile
- Automotive service

Each entity needs one canonical URL strategy and stable identifiers. Duplicate route variants must canonicalize to the preferred URL.

## Vehicle pages
Include only authoritative available facts:
- make/model/variant
- year
- price
- mileage
- location
- seller/showroom
- media
- listing status
- relevant specifications

Missing facts must not be fabricated for SEO.

## Showroom pages
Provide:
- canonical business identity
- location
- opening hours when provided/verified
- contact methods
- current inventory
- services
- reviews when legitimate
- verification status

Do not publish invented ratings, reviews, hours or inventory.

## Brand/model/city pages
Create useful indexable pages from real entities and inventory. Avoid thin doorway pages generated only to capture keywords.

## Structured data
Use appropriate schema.org JSON-LD where supported, including relevant Organization/AutomotiveBusiness/LocalBusiness, Product/Vehicle-related and BreadcrumbList structures. Values must match visible authoritative page content.

## Metadata
Every indexable route should have:
- unique title
- useful meta description
- canonical URL
- Open Graph metadata
- social preview image when available
- robots directives appropriate to publication state

## Sitemap
Sitemaps must include only canonical, indexable, published entities. Remove sold/deleted/private records according to their indexing policy.

## AEO
Answer common buyer questions directly and factually. FAQ content must be based on real product/business information. Do not generate false claims merely to answer a question.

## GEO
For city and local-intent pages, use authoritative location data, real showroom/service information and clear entity relationships. Avoid mass-generated city pages without meaningful local inventory or content.

## Internal linking
Connect:
Vehicle → Model → Brand → City → Showroom
and relevant services, without creating circular or excessive links.

## Reputation/trust
Reviews, verification badges, seller identity and claims must have traceable sources. User-generated content must be clearly separated from verified business facts.

## AI boundary
AI may draft titles, descriptions, FAQs, translations and schema suggestions, but publication requires validation against authoritative data. AI output is never the source of truth for marketplace facts.

## Release gate
SEO/AEO/GEO is a NO-GO if structured data disagrees with visible content, private/fake records are indexable, duplicate canonical URLs proliferate, or generated content makes unsupported factual claims.
